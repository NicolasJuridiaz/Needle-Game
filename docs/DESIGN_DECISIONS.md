# Design decisions & deviations from the GDD

Every significant deviation from `GDD_Project_Needle_V1.docx` is recorded here with its rationale.

| # | GDD | Decision | Why |
|---|-----|----------|-----|
| D1 | §17.3 recommends Godot 4 (web export) | **TypeScript + three.js + Vite** | Repo was empty and Godot is not installed. Native web stack: ~1–3 MB download vs ~10 MB+ Godot wasm, instant load (CrazyGames initial download ≤ 20 MB for mobile homepage), no SharedArrayBuffer headaches, headless Node simulation for automated balance playthroughs, and direct browser testing. Keeps the GDD's architecture (decoupled sim, chunks, instancing). |
| D2 | Pacing table: Piston Rake 16–19, Generator 19–22 | Generator plans are a prerequisite of the Rake (unlocked together ~15–19 min) | GDD §13 gives the rake 10 P of consumption, so it cannot run before power exists. Early generator is fed by hand (stoking) — a strong semi-manual phase that sets up the sell/burn trade-off early. |
| D3 | Sell Station and Order Board/Dock as separate objects | **Market Chute** sells everything and every delivery counts towards matching Orders; the Order Board is a wall display | Avoids "deliver here or sell there?" friction and duplicated belt destinations. Orders stay goals (deliver 20 bales, scan 2,000 hay, stable 40 hay/s...). |
| D4 | Splitter types Normal / Alternating / Priority / Overflow | One Splitter building with unlockable **modes**: Even (skips blocked outputs), Alternating (strict 1:1), Priority (2:1 weighted), Overflow (sides only when primary blocked), Smart (item filter) | In a discrete item sim "Priority: fill A first" and "Overflow: B only when A blocked" are identical; making Priority a weighted split keeps both nodes meaningful. Modes on one building = fewer shop items, same depth. |
| D5 | U-Splitter / U-Merger undefined | Compact **lane** splitter/merger (1 lane ↔ 2 parallel lanes, 1×2 footprint) | Fits "División compacta"; directly useful to feed two scanners side by side. |
| D6 | ~80 Work Tree nodes (GDD lists 111 rows) | *(RC1; superseded by D15)* **94 nodes / 109 purchasable levels**: "Speed I–II" style pairs are one node with 2 levels | Tree looks big and readable (~94 cards) while keeping every GDD upgrade. |
| D7 | Needle buff per needle index | Buffs granted in **discovery order** (1st found = +15% carry, ...) | Guarantees early buffs affect early systems regardless of which needle is found first. |
| D8 | Unscanned needle behaviour unspecified | Manual extraction finds needles instantly; machine-extracted needles travel hidden in hay packets; scanners detect deterministically; an unscanned needle reaching a sell/generator/compressor is **tossed back onto the pile** | Scanners matter, no RNG misses (GDD §11 rule), and needles can never be lost (no softlock). |
| D9 | Wheelbarrow as a tool | Pushable **world object**: park it, dig (overflow fills the barrow), push it (E) to sell/hopper | Physical, readable, avoids an awkward "equip a container" slot; keeps hotbar 1–6 as in GDD controls. |
| D10 | Level/building heights | Two build levels (floor + 2.5 m elevated). Elevated belts on stilts need no platform; machines on level 1 need platforms | Enables Belt Lift / ramps / crossing lines / platforms (GDD P0) without a full 3D voxel builder. |
| D11 | Mobile | Desktop (mouse + keyboard) only in V1; touch devices get a notice | First-person factory building needs precise pointer input; CrazyGames allows desktop-only submission. |
| D12 | §5 pile: ~150,000 virtual hay units | **RC2: 750,000 logical units** (RC1: 290k). Same pile geometry and hay grid: the size is only units per metre, so meshes, cells, draw calls and triangles do not change | Chosen from 50 bot seeds each at 500k / 650k / 750k (docs/PLAYTEST_V1.md §2). 750k: median 64.7 min, P90 68.9, Vacuum Collector and Scanner MK2 used in 100 % of runs, the biggest factory (18 arms, 195 buildings). 500k ends before the late machines matter (Collector used in 58 % of runs); 650k also works (median 61.9) but the player asked for the largest pile that keeps the pacing. |
| D13 | Work Points from needles, orders and milestones | **All WP sources give 163 WP; the RC2 Work Tree costs 224 WP (~73 %)**. No repeatable WP source | Every technology and level is reachable (tests/worktreeAudit.test.ts, tests/levels.test.ts), but a run cannot buy everything: choosing branches is the decision the tree exists for. Level upgrades also cost Money, so WP is not the only gate. Over 50 bot seeds (750k) a run earns 137-163 WP and buys 63 % of all levels. |
| D14 | Orders as a chain | Order DAG adjusted from bot data: **Steady Flow** (45 hay/s for a minute) opens after **Wholesale**, not after **Robot Friends** | When rakes saturate the first 50 hay/s trunk, new arms stay "Output blocked", Robot Friends cannot progress and there was no WP for Belt Speed: 5–10 min stalls at ~30 min in 1/3 of seeds. A saturated trunk now completes Steady Flow, which pays the WP for Belt Speed. |
| D15 | §6 Work Tree: one node per upgrade (RC1: 95 nodes) | **Level System (RC2)**: every tool and machine family is ONE technology with **Lv.1 -> Lv.5** (Lv.1 = plans; Hands starts at Lv.1). Lv.2-5 cost **WP + Money** in one purchase. Levels are **global per technology** (every unit placed before or after works at the technology level); a building never stores a level. Feature unlocks (splitter modes, U-variants, Belt Lift, Auto Feed, Auto Output, Dual Lane, platforms) stay separate nodes. Scanner Lv.5 = Scanner MK2 plans (MK1 and MK2 stay separate buildings, the tree shows one Lv.1-5 ladder). 39 nodes, 119 levels | Keeps the double progression (WP to research, Money to pay) while making the tree readable: a card shows "Lv x/5", its WP and $ price; the detail panel shows Now -> Next values, requirements and costs. Level requirements (e.g. Robotic Arm Lv.5 needs Conveyor Network Lv.3) keep the cross-branch structure. Belts, splitters and mergers follow the Conveyor Network level. |
| D16 | Raw Hay Value I (+25 % raw hay only) | **Hay Sell Value Lv.1 -> Lv.10**: x1.00, 1.10, 1.22, 1.35, 1.50, 1.68, 1.88, 2.10, 2.35, 2.65 on **every hay product** (raw hay, bales, wrapped bales). WP 1-3 per level; Money $1,500 -> $120,000, i.e. 2.5x (early) to 4x (Lv.10) the reference price of a normal upgrade of the same tier | Applying the multiplier to every product keeps processing worth it at every level (per hay used: bale >= 1.4x raw, wrapped >= 1.5x bale; tests/levels.test.ts). The steep price makes it a real trade-off against more machines: the bot reaches Lv.9 on average, near the end of the run. |
| D17 | RC1 prices | RC2 prices: tools -12 %, Hopper / Generator / Conveyor -16/-17 %, Piston Rake -17 % with price growth x1.22 (was x1.15), Robotic Arm -22 % ($7,000) with growth x1.10 (was x1.16), Scanner / Compressor / Wrapper / Silo -15 %, Vacuum Collector and Scanner MK2 -15 % (collector growth x1.15) | More, cheaper machines = a visibly bigger factory for the bigger pile (RC1 -> RC2, 50 seeds: arms 10.0 -> 18.3, buildings 146 -> 195, belt tiles 109 -> 145). Payback checked with real machines (tools/balance/payback.ts): no machine pays back in seconds at the moment it is typically bought; Piston Rake Lv.5 was cut from 92 to 50 hay/s after it paid back in 12-27 s. |
| D18 | Save format v1 | **Save v2** with a migration: RC1 technology = plans (Lv.1) + every old upgrade level of that family, capped at Lv.5; owning an old flagship node (MK2, Industrial Rake / Generator / Turbine, Double Chamber, Premium Wrap, dual outputs) gives Lv.5; Raw Hay Value I -> Hay Sell Value Lv.3; no money charged. Old saves keep their pile size | Favourable and conservative: nothing a player owned is lost, the factory keeps its ports and looks. Tested with a real RC1 late-game save (tests/saveMigration.test.ts). |
| D19 | Visual upgrade feedback | Lv.3: upgrade kit (armour plates with hazard stripes + amber beacon posts) on Piston Rake, Robotic Arm, Vacuum Collector, Scanner, Compressor, Generator; Lv.5: the existing Industrial / Advanced / MK2 / Premium models | The kit is rigged into the model's existing meshes (toggled by bone scale): more triangles, no extra draw calls. |
| D20 | Manual sale by pressing E on the Market Chute | **Visual iteration 1**: carried hay is sold only by **dropping it on a fixed SELL HAY intake belt** next to the chute (4 m, 1.8 s transit, not buildable, not purchasable); E on the chute sells nothing. The chute sells each load on arrival with the **same** `recordSale` call as before (manual, `viaBelt=false`): same prices, Hay Sell Value, orders and stats. A Store kiosk next to it opens the Shop | The loop becomes physical and readable (pile -> carry -> belt -> money) without touching the economy: the intake sits where the player already walked to sell (drop point ~2 m from the old one), the 1.8 s transit never blocks the player (drop and walk away), and 12 bot seeds before/after give the same completion times (docs/VISUAL_ITERATION_1.md). The strip x = -32 was the only column free in every real late-game factory we have (RC1 fixture, bot saves), so reserving it breaks no save. |
| D21 | Hay pile / hands look | Pile: flat-shaded faceted mesh with a 4-tone straw palette and low-poly straw lumps; no photo texture. Hands: bare low-poly hands with separate fingers instead of leather mitts | Stylised, readable at 907x510, cheaper than the textured look (fewer triangles on every preset, no hay texture upload). Render-only: the pile's shape, size and depletion still come from the unchanged sim heightfield. |
| D22 | Pile silhouette (B047) | **Visual Pass 2**: the rendered pile is a bounded visual mapping of the sim heightfield (flanks raised up to 1.6 m, crown lowered up to 2.4 m, secondary lobes), not the heightfield itself. Aiming, walking and needle drawing use the visual surface; digging uses the aimed X/Z through the existing extraction | Reads as a big heap of straw instead of a cone without touching the validated sim: 750k units, extraction, needle placement and depth bands, bot and saves are unchanged (bot results byte-identical on 12 seeds). A cell shows hay iff it has hay, so nothing visible is undiggable and nothing invisible is diggable. |
| D23 | Hands: how much a grab takes | **Hands Lv.1 -> Lv.5 = 1, 3, 6, 12, 20 hay per grab** (config/stamina.ts `HAND_LEVEL_PICKUP`, applied as additive steps on `tool.hands.dig` by the existing Hands levels; reach / width / speed perks unchanged). Carry capacity (20, Carry Capacity upgrades, bucket) is a separate stat and did not change | The owner asked for Lv.1 = 1 and Lv.5 = the old 20. "Per action" was read as per grab: holding the button still repeats grabs, so the early loop is slower but not a one-straw-per-trip grind. Other tools keep their own amounts. |
| D24 | Stamina | Player-only resource (src/sim/stamina.ts, values in config/stamina.ts): 100 max; sprint 12/s (only while moving with Shift); a manual grab costs 2 x hay^0.45 (Lv.1 = 2.0 for 1 hay, Lv.5 = 7.7 for 20 hay, ~5x cheaper per hay); hand vacuum 5/s; refills 25/s after 0.8 s idle; after running dry, sprint returns at 20. A grab that cannot be paid does not start (nothing taken, no cooldown, "Too tired" message). **Not saved**: a loaded game is rested (no save-schema change, nothing to corrupt) | Rhythm and a push towards automation without stop-and-wait: a full bar is ~8 s of sprint or ~50 Lv.1 grabs, and it refills in ~4 s. Machines, belts, robots and collectors never touch it (they never call the manual actions). |
| D25 | Map size / Market distance | **Compact hall**: east wall 32 -> 24, pile centre 5 -> -1 (new games), spawn between Market and pile. Nearest thick hay to the SELL HAY drop point 22.0 m -> 16.6 m (seed 1000; walk 4.8 s -> 3.6 s). Old saves keep their pile and every building (hay grid re-laid by columns; anything left outside the hall would be refunded) | The distance between pile and chute is also the room for the reference factory's trunk (rake, hopper, scanner, two splitters); 6 m was the most it could give without a different factory layout (the bot's processing line moved to a row north of the trunk). Floor for late game: 56 x 44 m hall + annex, the factory bounding box of a 55-min bot run is ~45 x 27 m. |

| D26 | UI look: warm brown panels, straw grain, gold gradients and glows, uppercase titles; HUD as scattered floating boxes (order top-centre, carry next to the crosshair, toasts under the needles) | **Industrial HUD pass**: one token set in `src/ui/styles.css` (neutral charcoal surfaces `--bg-0..4`, hairlines `--line..3`, off-white text `--ink..4`, one moderate straw accent `--acc`, state colours only for good / warn / bad, type scale `--fs-xs..xl`, small radii); no gradients, grain or glows. HUD in zones: economy plate top-left (Money; Work Points only once earned), goals column top-right (Needles, current Order, Power only with a generator), crosshair + prompt centre, player strip bottom-centre (Stamina, Hay carried, Barrow - each only while relevant), toasts left under the economy plate. Hotbar hides tools whose plans are not researched. Same class names, so every panel (Shop, Work Tree, Orders, Pause, Summary, Build HUD, tooltip, detector) moved to the same system | Readable with little colour, one game-wide look, less on screen early (a new game shows Money, Needles, Order, the Hands slot) and more only as systems unlock. CSS 1327 -> 1100 lines. |
